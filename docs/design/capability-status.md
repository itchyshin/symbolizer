# symbolizer capability surface

**Current development version:** 0.22.3
**Lifecycle:** experimental
**Scope:** this file is a capability inventory of what `symbolizer` exports and what evidence backs it — it is not a release certificate, not a claim that every rendered equation or interpretation is scientifically correct for a given dataset, and not a substitute for `NEWS.md` or the pkgdown reference index. Status words are exactly `covered | partial | experimental | planned`. When this file and `inst/extdata/capabilities.csv` disagree in wording, this file is the mapped projection — `capabilities.csv` is the machine-readable ledger (see "Registry relationship" below) and wins on any dispute about what `symbolize()` will actually let through the gate.

## What the package is for

`symbolizer` turns a fitted statistical model — distributional, multivariate, latent-variable, spatial, mixed-effect, meta-analytic, or additive — into a structured `symbolized_model` object, then renders that structure as publication-ready LaTeX equations, assumption tables, formula bridges, parameter interpretations, structural DAGs, methods-section paragraphs, and marginal-estimate summaries. It targets applied biologists and educators who need to audit *what a fitted model is actually saying*, not just fit it. First-class extractors exist for `drmTMB`, `gllvmTMB`, `glmmTMB`, `brms`, `lme4` (`lmer`/`glmer`), `MCMCglmm`, `sdmTMB`, base R `lm`/`glm`, `metafor` (`rma.uni`/`rma.mv`), `mgcv` (`gam`/`bam`), `phylolm`, and `piecewiseSEM`. It is complementary to `equatiomatic` for the model classes `equatiomatic` does not reach.

## Registry relationship

`inst/extdata/capabilities.csv` is the machine-readable source of truth for what `symbolize()` will actually let through: 136 `(class, family, component)` rows, each tagged with one of five registry status words (`Stable`, `First slice`, `Opt-in control`, `Planned or reserved`, `Unsupported or blocked`) — but today only three of the five actually occur in the data: `Stable`, `First slice`, and `Planned or reserved`. No row currently uses `Opt-in control` or `Unsupported or blocked`. `symbolizer_capabilities()` returns this table; `capability_check()` (internal) gates every `symbolize.*` method against it and errors with a pointer to the registry when a tuple is `Planned or reserved`. This document maps that fine-grained registry onto the house four-word vocabulary, one row per fitted-model class or per downstream rendering surface, and — per the audit brief for this file — cross-checks every registry claim against `tests/testthat/` (106 test files) rather than taking the CSV's status word on faith. Mapping convention used throughout: `Stable`/`First slice` rows with a real fitting test roll up to **covered**; rows where part of the declared scope has no fit-based test, or where the registry and the code visibly disagree, roll up to **partial** with the gap named explicitly; `Planned or reserved` rows are never claimed as capability — they appear only as the stated boundary of a covered/partial row.

## Important limits

- `symbolizer` is a read-only extractor and renderer. It does not fit models, does not validate that a user's model specification is scientifically appropriate, and does not check convergence — it renders whatever the upstream package's fitted object reports.
- A `Stable`/`First slice` registry status is a claim about *this repository's own code and tests*. The `drm_sem` row is the clearest counter-example: it is tagged Stable, but the extractor it describes lives entirely in the `drmSEM` package, so nothing in `tests/testthat/` here can verify it beyond the registry metadata's own shape. Treat any `lives_in` value other than `symbolizer` as a pointer to go verify in that other repo.
- `brmsfit` binomial and Poisson support (`mu`, `random_effects`, First slice since 0.11.2) is wired in `R/symbolize-brms.R` but has no fit-based regression test anywhere in this repo — every `brms::brm()` fixture in `tests/testthat/` uses `family = gaussian()`. Treat this specific pair of registry rows as unverified until a real bernoulli/binomial or Poisson `brm()` fit is added to the suite.
- `symbolize.bam` is a bare alias for `symbolize.gam` and internally always gates on `class = "gam"`, so the registry's dedicated `bam,*,*,Planned or reserved` row is unreachable dead documentation — the actual gate for a `bam` fit is whatever the matching `gam` row says. Separately, no test in this repo fits a real `mgcv::bam()` object, despite a test-file comment claiming that coverage.
- `drmTMB` and `gllvmTMB` are `Remotes:` (GitHub-only) `Suggests`, not CRAN dependencies; every test touching them is `skip_if_not_installed()`-gated, so a plain CRAN-only install of `symbolizer` will silently skip roughly half of the registry rows' test coverage (drmTMB: 34 rows; gllvmTMB: 25 rows) rather than fail.
- The five-level registry vocabulary (`Stable`, `First slice`, `Opt-in control`, `Planned or reserved`, `Unsupported or blocked`) is enforced by an invariant test (`test-capabilities.R`, "every status word is one of the five canonical values"), but only three of the five words are actually used anywhere in `capabilities.csv` today — `Opt-in control` and `Unsupported or blocked` are reserved vocabulary, not currently assigned to any row.
- The package is R-only; there is no Julia twin or cross-language parity claim (unlike `hsquared`/`HSquared.jl`).
