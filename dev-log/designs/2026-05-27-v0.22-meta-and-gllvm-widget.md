### A. Scope

**IN scope.**

- One conceptual model class: the **phylogenetic multilevel meta-analytic
  LMM** (Cinar et al. 2022, *MEE*, Eq. 1–10; Mizuno et al. 2026, *Research
  Synthesis Methods*, the unified phylo+spatial framework). The model is
  the structural-dependence article's model with `v_i` ESCALATED back IN:
  ```
  y_i | theta_i  ~ N(theta_i, v_i)              (v_i KNOWN per study)
  theta_i        = beta_0 + u_p_{k[i]} + u_s_{k[i]} + e_i
  u_p ~ N(0, sigma_p^2 * A),  u_s ~ N(0, sigma_s^2 * I),  e_i ~ N(0, sigma_e^2)
  ```
  Versus the v0.21.4 article where `v_i` was stripped and only `sigma_p^2 A`
  + `sigma_e^2 I` remained, here `v_i` is back as a third tier of variance
  (the known sampling tier).
- Three Faces, one deep-dive + two light:
  - **Face 1 (deep dive)**: `metafor::rma.mv(yi, V = vi, random = ~ 1 | species, R = list(species = A))`.
    Three-views widget. PDF download via `as_pdf_three_views()`.
  - **Face 2 (light)**: `brms::brm(yi | se(sqrt(vi)) ~ 1 + (1 | gr(species, cov = A)))`.
    Code + `equations()` + `assumption_table()` + `variance_components`,
    but no widget.
  - **Face 3 (light)**: `MCMCglmm::MCMCglmm(yi ~ 1, random = ~ species, ginverse = list(species = A_all$Ainv), mev = vi)`.
    Same surface treatment as Face 2.
- Article-level: shared grammar block (§1–§2 mirroring
  structural-dependence.Rmd lines 25–60), data block (§3 — reusing the
  60-species Moura aggregation from
  `vignettes/symbolizer-structural-dependence.Rmd` lines 64–141 with `v_i`
  retained), model statement (§4), per-Face sections, forward links,
  references.
- Σ-naming contract aligned with v0.21.4-redo: `sigma_p^2` for the
  phylogenetic species variance, `sigma_e^2` for the residual on the
  response scale, `v_i` for the known sampling variance. NEVER conflate
  these — the v0.21.4 article spent two audit cycles fixing exactly this
  conflation (V2 Pat F8, V3 Noether N3 in
  `symbolizer-hotfix/docs/dev-log/figure-audits/v0.21-redo-rescope/`).

**OUT of scope.**

- `glmmTMB::equalto(0 + obs | g, V)` Face — `equalto` is reserved but
  still unimplemented in glmmTMB ≤ 1.1.11 (confirmed by
  `vignettes/symbolizer-meta.Rmd` lines 178–190). Mention it as
  "planned upstream"; do not fit it.
- `glmmTMB::propto()` Face — `propto` introduces a free scalar multiplier
  on V, so it is NOT meta-analytic per se (v0.20 audit; see
  `vignettes/symbolizer-meta.Rmd` lines 107–155). Cross-link to the
  existing `symbolizer-meta` article rather than re-fitting.
- `drmTMB(sigma ~ 1 + offset(0.5 * log(vi)))` Face — distributional
  location-scale meta-analysis; covered in `vignettes/symbolizer-meta.Rmd`
  and `vignettes/symbolizer-drmtmb.Rmd`. Cross-link only.
- The spatial-meta-analysis surface from Mizuno et al. (2026). The unified
  phylo+spatial article is its own future surface (forward link to v0.23
  or v0.25, TBD).
- Multivariate meta-analysis (`rma.mv` with `struct = "UN"`, the
  bivariate-outcomes pattern). Already covered for `metafor` in
  `vignettes/symbolizer-meta.Rmd`. Leave for a later v0.22.x slice if needed.
- Publication-bias / selection models (Egger, PET-PEESE, RoBMA). Out of
  symbolizer's symbolic surface entirely.

### E. Article-level concerns

- **Pattern M** (no `htmltools::HTML(...)` wrap on widget chunks). The
  v0.21.4-redo `symbolizer-structural-dependence.Rmd` lines 206–248 are
  the correct template: `results = "asis"`, `message = FALSE`,
  `echo = FALSE`, and the widget is called bare:
  `as_html_three_views(sym_mcmc, id = "mcmc")` — no wrap. **Apply this
  pattern verbatim** to the meta-analysis Face-1 widget chunk.
  Caught-today regression: see `symbolizer-hotfix` commit `ca7626d`
  ("Pattern M fix: drop htmltools::HTML() wrap on families.html widgets")
  and the GLLVM Florence audit
  (`docs/dev-log/figure-audits/phase0a-gllvm/V1-florence-lens-report.md`
  lines 21–55: two complete widget copies, duplicate IDs).
- **Pattern N** (gloss prose with raw LaTeX — keep math fragments in
  `$...$`). The v0.21.4 article has a `\boldsymbol{\Lambda}_B` leak in
  the Section 7 heading that surfaces in the TOC slug (GLLVM Florence
  audit lines 57–62). For the meta-analysis article: when writing
  section headings with math, use either plain unicode (e.g. "σ_p²") or
  wrap in `\(...\)` MathJax (NOT `$...$` — `$$` is for display math, `$`
  collapses to inline-text mode in pandoc's vignette renderer). Audit
  the TOC + slug text after each build.
- **Pattern O** (matrix col truncation). The hotfix branch
  (`symbolizer-hotfix` commit `fe688eb`) lands the
  `head_cols` / `tail_cols` arguments on `as_html_three_views()` and
  `as_pdf_three_views()`. For the meta-analysis article: the `A` matrix
  is 60×60, so the default `head_cols = 5, tail_cols = 2` works. The
  random-effect design `Z_g` is 60×60 (one obs per species), also fine.
  Worth checking after first build whether the diagonal of `A` reads
  well — A's off-diagonals are mostly < 0.1 in the Moura aggregation;
  the widget should show clear structure.
- **σ_p / σ_e naming consistency.** Use `sigma_p^2` (the species-level
  phylogenetic variance) and `sigma_e^2` (the residual on the response
  scale), matching v0.21.4 lines 156–169. NEVER write `tau^2` for the
  species variance (that's metafor's name for between-study heterogeneity
  in `rma`, distinct from `sigma^2` in `rma.mv`). The article's symbol
  table must include a footnote on package-level naming drift:
  - metafor `rma.mv`: variance components are `sigma^2_j` per tier
  - metafor `rma.uni`: between-study variance is `tau^2`
  - brms / MCMCglmm: per-group SDs are reported, not variances
  - drmTMB: `sigma_p` (location-scale convention; see `vignettes/symbolizer-meta.Rmd` lines 213–235).
- **V_i symbol contract (Cinar 2022 Eq. 9).** Cinar et al. (2022, *MEE*)
  use `v_i` (lowercase italic, scalar per observation) for sampling
  variance and `V` (uppercase upright bold) for the full covariance
  matrix (`V = diag(v_1, ..., v_k)` in the standard case, or block-
  diagonal with within-study correlations in the multivariate
  meta-analysis case). The article uses `v_i` in scalar form and `V` in
  matrix form; the `metafor::rma.mv(V = V, ...)` argument name uses the
  matrix form. Match Cinar throughout — a copy of Eq. 9 in §4 with the
  exact same letters is the cleanest pedagogy.
- **Citation integrity (V3 Noether N2 from v0.21.4).** Cinar et al. is
  **2022** (not 2021). The v0.21.4 article had this wrong in a trip-up
  note; do not propagate. DOI: 10.1111/2041-210X.13760.

### G. Open questions for the maintainer

1. **Article filename and vignette index.** Two candidates:
   - `vignettes/symbolizer-meta-analysis.Rmd` (full and discoverable;
     parallels `symbolizer-structural-dependence.Rmd`)
   - `vignettes/symbolizer-meta-phylo.Rmd` (narrower; conveys the
     phylogenetic-meta scope)

   The existing `vignettes/symbolizer-meta.Rmd` is the "three faces of
   meta-analysis syntax" tutorial (a syntax tour, not a model-class deep
   dive). The two should coexist (different audiences). Recommend
   `symbolizer-meta-analysis.Rmd` for the v0.22 deep dive — the longer
   name signals "this is the deep dive" — but maintainer call.

2. **Dataset choice.** The Moura subset already exists in v0.21.4-redo
   and reusing it has these advantages:
   - Same 60-species fixture → readers who read v0.21.4 first see the
     "what if v_i were kept" story land directly on a familiar dataset.
   - Same A matrix → the Cov(u) block in Tab 3 of the widget will read
     similarly across both articles, locking in the symbol contract.
   - Same chronos / inverseA pipeline → the article's data block can be
     short (it's a delta on v0.21.4 §3, not a new fixture).

   Alternatives that the maintainer may prefer:
   - The classic Mizuno tutorial dataset (smaller, illustrative-only)
   - `dat.cinar2022` (Cinar's MEE 2022 simulation-study dataset, if it's
     in metadat) — would give a one-paper-one-dataset story
   - A simulated dataset with known `sigma_p^2` and `v_i` for recovery
     testing

   Recommend Moura (continuity with v0.21.4). Audit note: if reusing,

### C. Required extractor work

The widget needs `sym$expanded` populated richly enough for
`as_html_three_views()` to find:
- `y` (response vector)
- `X` (fixed-effects design matrix)
- `beta` (estimated fixed-effects vector)
- `Z_g` (random-effects design matrix, n × n_random_levels)
- `u` (random-effects BLUPs, n_random_levels × 1)
- `mu_hat` (predicted mean per observation)
- `fitted` (= `mu_hat`)
- `residuals` (= `y - mu_hat`)
- Optional: `M` (the structured-covariance matrix; only used by Tab 3's
  Cov(u) display in v0.21.4-redo)

**What `R/symbolize-gllvmtmb.R` currently produces** (`glm_build_expanded()`
lines 841–876): `list(y, Y, mu = b_fix, Lambda_B, Z_B, Sigma_B, sigma_eps, eta)`.

The shapes are wrong for the widget:
- The widget expects `mu_hat` (predicted mean per observation), not `mu`
  (the per-trait intercept vector).
- The widget expects `X` and `beta` to multiply into the per-row predicted
  mean. In gllvmTMB, the design matrix is the trait factor (`0 + trait` →
  one-hot per row); `beta` is the trait-intercept vector.
- The widget expects `Z_g` (the random-effects design) and `u` (the
  per-level BLUPs). In a GLLVM, the analogous quantity is `Z_B` (the unit
  latent scores) × `Lambda_B^T` (so the unit-level random contribution
  for row j is `(Lambda_B z_{B,i})_{t(j)}`).

Two options for the v0.21.5-redo / v0.21.6-redo slice:

**Option 1 — extractor change.** Modify `glm_build_expanded()` to
populate `mu_hat`, `Z_g`, `u`, and the additional `M = Sigma_B` matrix
so the widget renders out of the box. Pseudocode for the additions:
```r
glm_build_expanded <- function(fit, trait_levels) {
  # ... existing code ...
  # New for widget compatibility:
  X_long <- model.matrix(~ 0 + factor(data[[fit$trait_col]],
                                       levels = trait_levels))
  beta_hat <- fit$report$mu %||% (per-trait intercept vector)
  # Per-row latent contribution: (Lambda_B %*% Z_B[i,])[t(j)]
  Z_B <- as.matrix(getLV(fit, level = "unit"))
  Lambda_B <- as.matrix(fit$report$Lambda_B)
  # Build Z_g as the (n_obs × n_unit*d_B) Khatri-Rao product of trait
  # indicators × unit indicators (this is the long-format design matrix
  # that maps per-row to per-(unit, trait) contributions)
  # ... (this is the tricky part — see Option 2)
  list(
    y = y_long, Y = Y, X = X_long, beta = beta_hat,
    Z_g = Z_g, u = vec(Z_B),
    M = fit$report$Sigma_B,
    mu_hat = X_long %*% beta_hat + (Lambda_B %*% Z_B[site_id, ])[trait_id],
    fitted = mu_hat,
    residuals = y_long - mu_hat,
    Lambda_B = Lambda_B, Sigma_B = fit$report$Sigma_B,
    Z_B = Z_B, sigma_eps = fit$report$sigma_eps,
    eta = fit$report$eta
  )
}
```
The `Z_g` for a GLLVM is `n_obs × (n_units × d_B)` where each column
corresponds to one (unit, axis) pair; the entries are
`lambda_{B,t(j),k}` (sparse on the trait dimension). This is genuinely
non-trivial — it's the right answer but takes careful indexing.

**Option 2 — vignette shim** (recommended for the v0.21.x slice). Match
the v0.21.4-redo pattern: write a `shim_gllvm()` function inline in the
vignette (echo = FALSE) that builds the widget-compatible expanded list
from the symbolized fit's existing pieces. This is exactly the
`shim_mcmcglmm()` pattern (`vignettes/symbolizer-structural-dependence.Rmd`
lines 216–245). The shim can be promoted into the extractor in v0.22 or
v0.23 once its shape stabilises.

The shim approach is recommended because:
- It avoids touching `R/symbolize-gllvmtmb.R` (which is currently in
  First-slice state and stable; adding `Z_g` machinery risks breaking
  the existing GLLVM tests).
- It makes the widget's expected `expanded` shape explicit in the
  vignette, which helps document the contract for future extractor
  refactors.
- v0.21.4-redo establishes this pattern; mirroring it keeps the dev-log
  story consistent.

**Capabilities row.** No new row needed — the gllvmTMB Gaussian /
binomial × `Lambda_B` / `Psi_B` / `sigma_eps` rows
(`inst/extdata/capabilities.csv` lines 33–47) already cover everything
the widget displays. The widget is a renderer, not a new capability.
